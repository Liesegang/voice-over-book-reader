# 追加機能の計画

以下の追加機能は未実装です。
Chromiumによる本文表示の実装と検証を先に完了し、追加機能は計画だけを作成します。
既存機能と追加する範囲を分け、方式の提案は採用済みと扱いません。

## 決定済みの範囲

| 案の番号 | 対象 |
| --- | --- |
| 3 | 章・本の音声事前生成とオーディオブック出力 |
| 4 | 本ごとの設定 |
| 6 | 日本語に対応するローカル全文検索索引 |
| 7 | 辞書検索の原形処理統一、範囲修正、履歴 |
| 8 | 本棚のソートと条件で選ぶスマート本棚 |
| 10 | ショートカットの重複表示と置換・取消 |

案10にはコマンドパレットを含めません。
書籍、Calibreライブラリ、MDX／MDDの原本は変更せず、追加データはアプリ側へ保存します。

## 依存関係と着手順の提案

Chromium側の選択、検索結果、辞書、読み上げが、同じ原文位置を扱えることを前提にします。
本文の組版や文字方向を変えても、ページ番号ではなく原文の位置で参照を保持します。

| 順序案 | 内容 | 先に必要なもの |
| --- | --- | --- |
| 1 | 本ごとの設定と保存形式 | 既存設定との継承規則 |
| 2 | 検索索引と辞書検索の統一 | Chromiumから原文位置への対応 |
| 3 | 本棚のソートとスマート本棚 | 条件式と読書状態の定義 |
| 4 | 音声事前生成と書き出し | 本ごとの音声設定、生成ジョブ |
| 独立 | ショートカットの重複確認 | 既存アクション一覧 |

この順序は実装の依存を減らすための提案です。
優先順位、データ形式、各画面の詳細は、追加機能へ着手する前に確定します。

## 3. 音声の事前生成と書き出し

現在はページ付近の先読み、生成音声のキャッシュ、再生中の後続章の準備があります。
MP3、M4A／M4B、WAVの読込・再生も実装済みですが、書き出し機能はありません。
根拠は[音声制御](../crates/reader-speech/src/engine.rs)、[音声キャッシュ](../crates/reader-speech/src/cache.rs)、[録音済み音声の再生](../crates/reader-speech/src/audiobook.rs)です。

追加案では「この章」「選んだ章」「本全体」を指定して事前生成します。
再生と同じ文章の分割、声、読み登録を使い、生成済みの音声は再利用します。
元速度の音声を保存し、0.5〜10倍速への変更は再生時に適用する方式を提案します。
これにより、速度を変えるたびの再生成を避けます。

生成ジョブには、書籍の内容版、声とモデル、読み登録の版、完了した区間を保存する案です。
中断や再起動後は未完成の区間から再開します。
途中で設定が変わった場合は、新旧の声や読みを一つの出力に混ぜません。
再生要求と直近の先読みを優先し、書き出し処理による推論の並列数と保存容量を制限します。

推奨する出力形式は、章情報を含むM4Bと、章別のWAVです。
M4B用の音声エンコーダーは、対応OSと配布条件を確認してから選定します。
既存のM4B再生対応だけを、M4B書き出し対応とは扱いません。
MP3を初回の対象に含めるかは未決定です。

本文と生成音声を再び対応させるため、原文位置と実音声の境界を別ファイルへ保存する案です。
APIキー、モデル本体、ローカルパスは出力に含めません。
生成音声に適用される条件は、選択した声ごとに確認します。
確認済みの範囲は[音声のライセンス確認](license-audit.md)を引き継ぎます。

操作は本の右クリックメニューと読書メニューへ置き、進捗は小さなジョブ一覧にまとめる案です。
処理中の通知で本文を繰り返し覆いません。

受入条件は次のとおりです。

- 中断・再起動後に、完成した区間を再合成せず再開できる。
- 事前生成済みの区間は、10倍速でも推論待ちで止まらない。
- 声、読み登録、原文位置、境界精度を保存前後で維持する。
- 書き出した音声を再読込し、章移動と長時間のシークを検証できる。
- 容量不足や取消で、既存の完成ファイルを破損しない。

## 4. 本ごとの設定

現在の外観、音声、読み登録は全体設定です。
音声エンジンごとの声の保持は既にあるため、追加対象は書籍単位での上書きです。
根拠は[設定](../crates/reader-library/src/settings.rs)と[音声プロファイル](../crates/reader-app/src/speech_profiles.rs)です。

全体設定を基本に、本ごとには変更した項目だけを保存する方式を提案します。
対象候補は文字方向、フォント、文字サイズ、ルビ、余白、声、速度、自動追従、読み登録です。
各項目を「全体設定を使う」へ戻せるようにします。
書籍固有の読み登録が全体の読み登録より優先する案です。

保存には既存の書籍IDを使い、内容変更を検出する識別子は別に持ちます。
接続先の認証情報を本ごとに複製せず、音声設定から既存の接続情報を参照します。
モデルを保持するための識別子と読み登録の版を分け、読み登録の編集でモデルを再起動しない設計を含めます。

設定画面の上部で「全体」「この本」を切り替える案です。
ラベルは左、スイッチは右に配置し、上書きした項目と継承中の項目を見分けられるようにします。

受入条件は次のとおりです。

- 2冊を同時に開き、異なる設定を保存・再読込できる。
- 全体設定の変更は、書籍側で上書きしていない項目だけへ反映する。
- 書籍の上書きを解除すると、その時点の全体設定へ戻る。
- 読み登録の変更で、無関係な音声キャッシュと音声モデルを作り直さない。
- 旧設定、ブックマーク、読書位置を移行で失わない。

## 6. 日本語のローカル全文検索索引

現在も本全体を検索できます。
各章を読み込み、本文と表の文字列を照合する方式で、永続的な全文検索索引はありません。
根拠は[書籍の検索](../crates/reader-core/src/document.rs)です。

本文の検索用データと、原文位置への対応をアプリ側へ保存する案です。
索引はバックグラウンドで作成し、書籍の内容版と抽出処理の版で再利用を判断します。
読み上げ用のルビを親文字と重複させず、表示本文を検索対象にします。

日本語の短い語、句読点を含む語句、全角・半角の違いを検証します。
文字の正規化や索引方式を選ぶ際は、一致箇所を元の文字範囲へ戻せることを条件にします。
索引作成前と作成後の結果を照合し、件数だけでなく選択範囲も確認します。
索引が未完成なら作成中と示し、途中の結果を検索完了とは扱いません。

UIは既存の検索サイドバーを使い、検索語の周辺を抜粋します。
表示した結果から、未ロードの章や組版変更後の位置へ移動できるようにします。

受入条件は次のとおりです。

- 日本語の1文字・2文字検索と、複数の語にまたがる検索が欠落しない。
- ルビ、表、正規化した文字でも、原文の一致範囲を選択できる。
- 書籍更新時に古い索引の結果を混ぜず、破損時には再作成できる。
- 検索を続けて入力しても、古い検索の結果で新しい結果を上書きしない。
- 初回の索引作成と再検索を別々に計測し、既存の全章走査と比較する。

## 7. 辞書の原形処理、範囲修正、履歴

既に形態素解析による単語範囲と原形の取得があります。
辞書の結果を縦に並べ、右の一覧で移動する表示、検索語の編集、固定も実装済みです。
追加対象は、呼び出し方法による検索語の違いをなくし、選択範囲の修正と履歴を使えるようにすることです。
根拠は[単語解析](../crates/reader-core/src/words.rs)、[Chromiumからの辞書検索](../crates/reader-app/src/cef_reader.rs)、[辞書の表示仕様](dictionaries.md)です。

本文クリック、右クリック、キー操作で、同じ原文から同じ検索候補を作る方式を提案します。
原形と表記が異なる場合は両方を候補にし、利用者が直接入力した検索語は保持します。
複合語や人名を自動選択し損ねた場合は、本文上で範囲を伸縮して再検索できるようにします。

履歴には検索語と参照位置を保存し、前後移動、個別削除、全削除を追加する案です。
履歴の保存件数と、保存を無効にする設定は未決定です。
MDX／MDDは変更しません。

操作は既存ポップアップの検索欄付近にまとめます。
範囲修正や履歴移動のたびに、固定状態、辞書の表示順、ウィンドウ位置を初期化しません。

受入条件は次のとおりです。

- 同じ箇所を各操作で引くと、表記・原形の候補と順序が一致する。
- 複合語や活用形の範囲を修正し、その範囲だけで検索できる。
- 履歴から戻る際に、検索語と元の参照位置を再現できる。
- 履歴を削除しても、辞書本体とブックマークには影響しない。

## 8. ソートとスマート本棚

現在は表紙表示、行リスト表示、読書状態の絞り込み、自分で本を入れる本棚があります。
追加対象は並べ替えと、保存した条件に合う本を自動で表示するスマート本棚です。
根拠は[本棚の表示と絞り込み](../crates/reader-app/src/app.rs)と[本のメタデータ](../crates/reader-library/src/store.rs)です。

ソート候補は書名、著者、追加日時、最終読書日時、進捗です。
昇順・降順を選び、同じ値の本も順序が安定する方式を提案します。
日本語の読み順や巻数の自然な並びは、利用できるメタデータを確認して仕様を決めます。

スマート本棚には、著者、タグ、読書状態、進捗、最終読書日時による条件を保存する案です。
保存するのは条件で、手動の本棚の本の一覧とは分けます。
Calibreの再読込や読書状態の変更で、該当する本を更新します。

並べ替えは本棚上部、スマート本棚の作成は既存の本棚追加操作へまとめる案です。
条件編集は左揃えの行で表示し、絞り込み結果の冊数を確認できるようにします。

受入条件は次のとおりです。

- 表紙と行リストで、同じ絞り込みと並べ替えを維持する。
- 欠けた著者や日時の扱いを決め、再起動後も順序を再現する。
- 読了やタグ変更の後に、スマート本棚の対象が更新される。
- 手動の本棚をスマート本棚へ勝手に変換しない。
- 設定変更で、Calibreの原本やメタデータへ書き込まない。

## 10. ショートカットの重複確認

現在も全アクションのキー割り当てを変更できます。
新しい割り当てが既存のキーと重なると、既存の割り当てを自動で解除する処理があります。
追加対象は、重複を見せてから置換か取消を選ぶ操作です。
根拠は[アクション一覧](../crates/reader-app/src/actions.rs)、[割り当て処理](../crates/reader-app/src/app.rs)、[設定画面](../crates/reader-app/src/settings.rs)です。

固定アクションと自分の本棚への移動を、同じ重複判定に含める案です。
重複時には、使われるキーと該当するアクション名を表示します。
「置き換える」で競合した割り当てだけを解除し、「キャンセル」では保存済みの設定を変更しません。
初期値への復元も同じ確認を通します。

重複表示はキー割り当て行の直下へ置き、アクション名を左揃えで示します。
画面幅を圧迫しない範囲で、キー入力欄と操作ボタンの位置を揃えます。

受入条件は次のとおりです。

- 初期値、保存した割り当て、本棚移動の重複をすべて表示する。
- 取消では、変更前の割り当てがそのまま残る。
- 置換では、競合しない割り当てを維持する。
- OSごとの修飾キーと入力中のキー捕捉を、実行時と同じ規則で扱う。
- コマンドパレットを追加しない。
