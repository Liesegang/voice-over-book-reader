# Chromium本文表示の性能測定

同じWindows端末で比較したところ、Chromium版の通常のページ送りは旧ネイティブ版と同程度でした。
本文の初回表示、連続ページ送り、メモリ使用量には増加が残っています。
Chromium版内の調整で連続ページ送りの時間は短くなりましたが、旧版の値には達していません。

測定日は2026年10月31日です。
[測定条件と集計値](benchmarks/chromium-2026-10-31.json)を、以下の数値の根拠としています。
各条件3回の記述的な比較で、統計的な有意差や他の端末での速度を示すものではありません。

## 比較対象と測り方

| 項目 | 旧ネイティブ版 | Chromium版 |
| --- | --- | --- |
| ソース | `98d2c8d` | `77428d5` |
| Rust | 1.97.0 | 1.97.1 |
| WindowsのCランタイム | 動的リンク | 静的リンク |
| 本文表示 | 独自のネイティブ組版 | Chromium Embedded Framework |

CPUはRyzen 9 3900X、物理メモリは63.9 GiB、GPUはRTX 3090です。
OSはWindows 11 Proを使いました。
両版を同じ測定プログラムで起動し、アプリと子プロセスを含めて測りました。
ツールチェーンとランタイムの構成も異なるため、差を描画エンジンだけの効果とは扱えません。

時間の起点は、外部の測定プログラムがアプリを起動する直前です。
Windowsの高精度カウンターを使い、実行ファイルと起動処理の読込時間も含めます。
各項目の終点は次のとおりです。

| 項目 | 終点 |
| --- | --- |
| 本文の初回表示 | 操作可能な本文をGPU画像の読戻しで確認 |
| 通常のページ送り | 入力後の対象ページをGPU画像の読戻しで確認 |
| 5ノッチの連続ページ送り | 5ページ分の画像を順に確認 |
| 全ページ数の確定 | 操作可能な本文と、現在の組版による全体の索引を確認 |

画像の読戻しには取得と通知の時間が加わります。
次のフレームを取得して確認する方式で、ディスプレイが実際に発光するまでの時間ではありません。
過去の純粋な組版処理やCPUフレーム作成時間とは、測定の範囲が異なります。

「初回」は設定だけの新しいアプリデータを使い、保存されたページ索引を持たない状態です。
OSのファイルキャッシュとGPUのキャッシュは消去していません。
「索引再利用」は同じ版を再起動し、保存したページ索引を使う状態です。
読書位置を削除して同じ設定に戻し、Chromiumのプロファイルはプロセスごとに新しく作ります。
ブラウザーのプロファイルを継続利用した起動速度ではありません。

## 単章の本文表示とページ送り

表は各条件3回の中央値です。
通常のページ送りは、各回30操作の中央値を求め、その3回の中央値を示します。
連続ページ送りはホイール5ノッチ分を一度に入力し、実際の5ページを順に確認するまでの時間です。

| 状態 | 項目 | 旧版 | Chromium版 |
| --- | --- | --- | --- |
| 初回 | 本文の初回表示 | 989.95 ms | 1,932.30 ms |
| 初回 | 通常のページ送り | 65.114 ms | 62.315 ms |
| 初回 | 5ノッチの連続ページ送り | 115.04 ms | 251.48 ms |
| 索引再利用 | 本文の初回表示 | 980.01 ms | 1,876.34 ms |
| 索引再利用 | 通常のページ送り | 65.144 ms | 62.764 ms |
| 索引再利用 | 5ノッチの連続ページ送り | 116.57 ms | 246.32 ms |

単章のページ数は旧版が51ページ、Chromium版が52ページでした。
組版エンジンによって改ページ位置が異なるため、1回のページ送りで進む文字数は同一ではありません。
この測定は操作応答の比較で、同じ文字量を表示する処理速度の比較ではありません。

## 30章・120ページの起動から全ページ数確定まで

両版で120ページになった30章の検証用EPUBを使いました。
以下はアプリの起動を含み、全ページ数が画面上で確定するまでの時間です。
純粋なページ数計算の時間ではありません。

| 状態 | 旧版 | Chromium版 |
| --- | --- | --- |
| 初回 | 922.86 ms | 3,329.28 ms |
| 索引再利用 | 929.06 ms | 1,560.06 ms |

Chromium版はページ数の計算をバックグラウンドで進め、結果を保存して再利用します。
今回の索引再利用では初回より確定が早まった一方、旧版より時間がかかっています。
起動と索引計算を分けた追加測定が、残る遅延の分析に必要です。

## プロセスのメモリ

ルートプロセスと、その子として記録したプロセスについて、Private Bytesの合計を定期的に記録しました。
表は各回の最大サンプル値を求めたうえで、3回の中央値を示します。
Private Bytesはプロセス固有の割り当てを表し、GPUのVRAMを含みません。

| 対象 | 状態 | 旧版 | Chromium版 |
| --- | --- | --- | --- |
| 単章 | 初回 | 441.73 MiB | 747.54 MiB |
| 単章 | 索引再利用 | 444.49 MiB | 746.43 MiB |
| 30章 | 初回 | 433.83 MiB | 947.93 MiB |
| 30章 | 索引再利用 | 382.86 MiB | 629.17 MiB |

単章で、各回のサンプル間隔の中央値は約195〜212 msでした。
短いピークや、サンプル間で起動・終了した子プロセスを記録できない場合があります。
したがって、この値は記録したサンプルの最大値で、真のピークの下限です。
常駐メモリやVRAMを含む端末全体の使用量としては扱いません。

## Chromium版内の連続ページ送りの調整

同じ測定プログラムによる調整前のChromium版と最終版の比較です。
ページ操作を同時に重ねて送らず、ページ操作とキューの処理を1回の呼出しにまとめました。
必要なZIP内の資源だけを読み込む処理、全体のページ索引のバックグラウンド計算と保存も使います。

| 状態 | 調整前のChromium版 | 最終Chromium版 |
| --- | --- | --- |
| 初回・5ノッチ | 402.13 ms | 251.48 ms |
| 索引再利用・5ノッチ | 400.83 ms | 246.32 ms |

初回の連続ページ送りは、3回の中央値の比較で37.5%短くなりました。
別の測定一式を比較した結果であり、各変更が何ms短縮したかを切り分けた値ではありません。
通常のページ送りの時間が近づいても、初回表示とメモリの増加は残っています。

## 確認した動作と適用範囲

2種類のEPUB、2つの版、初回と索引再利用を各3回、合計24回起動し、全測定で成功を確認しました。
単章の12起動では、各30回のページ送り、5ノッチの順序、メニューを重ねた際の本文配置を確認しています。
Chromium版では、実際に読み込まれたクライアントDLLのハッシュが想定した値と一致しました。
索引再利用の測定では、保存した索引のハッシュも変わっていません。

この結果から、macOS、Linux、別のGPUや実書籍での性能は判断できません。
音声合成と音声出力の速度も、この比較の対象外です。
書籍の原文、ローカルパス、測定画像は公開資料に含めません。
